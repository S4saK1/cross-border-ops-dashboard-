# ADR-003: 导出流程添加一致性检测阻断
**状态:** Proposed
**日期:** 2024-01-15

## 背景
当前导出流程直接导出产品数据，没有检查数据一致性。根据技术债评估报告#7，需要在导出API中嵌入一致性检测逻辑，确保导出数据的质量。

## 选项分析

### 选项A: 导出前强制检查，错误时阻断
| 维度 | 评估 |
|------|------|
| 复杂度 | Medium |
| 成本 | 中 - 需要集成一致性检测引擎 |
| 可扩展性 | 优 - 确保数据质量 |

**优点：**
- 确保导出数据质量
- 防止错误数据流出
- 符合质量管理要求

**缺点：**
- 可能影响导出性能
- 需要处理检查失败的情况

### 选项B: 导出时检查，警告但不阻断
| 维度 | 评估 |
|------|------|
| 复杂度 | Low |
| 成本 | 低 - 只需添加检查逻辑 |
| 可扩展性 | 中 - 允许用户选择是否继续 |

**优点：**
- 用户体验好，不阻断操作
- 实现简单
- 用户可自行决定是否继续

**缺点：**
- 可能导出错误数据
- 无法保证数据质量

### 选项C: 后台异步检查，导出后通知
| 维度 | 评估 |
|------|------|
| 复杂度 | High |
| 成本 | 高 - 需要异步处理机制 |
| 可扩展性 | 中 - 用户体验好但实现复杂 |

**优点：**
- 不影响导出性能
- 用户体验好
- 可以处理大量数据

**缺点：**
- 实现复杂
- 无法立即反馈问题
- 需要额外的通知机制

## 决策
推荐**选项A: 导出前强制检查，错误时阻断**，理由如下：
1. **数据质量优先**：确保导出数据符合质量要求
2. **实现成本适中**：利用现有的一致性检测引擎
3. **用户体验明确**：错误时明确提示，避免混淆
4. **符合业务需求**：跨境产品资料必须保证一致性

## 具体实现方案

### 检测逻辑集成
1. **在导出API中集成ConsistencyEngine**
   ```python
   @router.post("/csv")
   def export_csv(req: ExportRequest, db: Session = Depends(get_db)):
       # 1. 获取产品数据
       products = get_products(req.product_ids, db)
       
       # 2. 执行一致性检查
       consistency_engine = ConsistencyEngine(db)
       all_issues = []
       for product in products:
           issues = consistency_engine.check_product(product)
           all_issues.extend(issues)
       
       # 3. 检查是否有ERROR级别问题
       error_issues = [i for i in all_issues if i["severity"] == "ERROR"]
       if error_issues:
           raise HTTPException(
               status_code=400,
               detail={
                   "message": "数据一致性检查失败",
                   "errors": error_issues,
                   "suggestion": "请先修复数据一致性问题再导出"
               }
           )
       
       # 4. 执行导出
       return generate_csv(products, req.platform)
   ```

### 错误处理策略
1. **ERROR级别问题**：阻断导出，返回400错误
2. **WARNING级别问题**：允许导出，但在响应中添加警告
3. **INFO级别问题**：自动修复或忽略

### 性能优化
1. **批量检查**：一次性检查所有产品，避免重复计算
2. **缓存机制**：缓存术语词典和规则数据
3. **异步处理**：对于大量产品，考虑异步检查

### 用户体验优化
1. **错误信息详细化**
   ```json
   {
       "message": "数据一致性检查失败",
       "errors": [
           {
               "severity": "ERROR",
               "field": "颜色",
               "zh_term": "颜色",
               "found_values": ["Red", "red", "RED"],
               "suggestion": "Red",
               "affected_products": ["SKU001", "SKU002"]
           }
       ],
       "total_errors": 1,
       "total_warnings": 3
   }
   ```

2. **提供修复建议**
   - 指出具体问题字段
   - 提供标准值建议
   - 列出受影响的产品

3. **分步处理选项**
   - 先检查后导出
   - 提供"强制导出"选项（仅限WARNING级别）
   - 导出检查报告

## 影响
### 变容易
- 数据质量得到保证
- 防止错误数据流出
- 提高用户对数据的信任度

### 变困难
- 导出流程可能变慢
- 需要处理更多的错误情况
- 用户可能需要先修复数据

### 需要重新审视的部分
- 现有导出流程
- 一致性检测引擎性能
- 错误处理机制
- 用户界面设计

## 性能考虑
1. **检查时间估算**
   - 单个产品检查：< 10ms
   - 100个产品检查：< 1s
   - 1000个产品检查：< 10s

2. **优化策略**
   - 并行检查多个产品
   - 缓存检测规则
   - 索引优化数据库查询

3. **超时处理**
   - 设置合理的超时时间
   - 大数据量时分批处理
   - 提供进度反馈

## 测试验证方案
1. **功能测试**
   - ERROR级别问题阻断导出
   - WARNING级别问题允许导出
   - 检查结果正确性

2. **性能测试**
   - 不同数据量下的检查时间
   - 并发导出性能
   - 内存使用情况

3. **边界测试**
   - 空数据集处理
   - 超大数据集处理
   - 网络异常处理

4. **用户体验测试**
   - 错误信息可读性
   - 修复建议实用性
   - 流程顺畅度
