# ADR-006: PostgreSQL 数据库迁移路径

**状态:** Accepted  
**日期:** 2026-07-23
**更新:** 2026-07-31 — 生产环境已启用 PostgreSQL

## 背景

当前系统使用 SQLite 作为默认数据库，适用于开发和测试环境。然而，SQLite 存在以下限制：

1. **不支持多主节点写入**：无法支持多实例部署和负载均衡
2. **并发写入限制**：高并发场景下性能受限
3. **数据完整性**：缺乏完整的事务支持和外键约束
4. **扩展性**：无法满足生产环境的高可用性要求

## 选项分析

### 选项 A: 保持 SQLite 作为唯一数据库
| 维度 | 评估 |
|------|------|
| 复杂度 | Low |
| 成本 | Low |
| 可扩展性 | Low |
| 维护性 | High |
| 生产适用性 | Low |

**优点：**
- 零配置，开发体验好
- 无需额外基础设施
- 适合小型项目和原型

**缺点：**
- 无法支持生产环境高可用性
- 并发性能受限
- 缺乏企业级特性（复制、备份、监控）

### 选项 B: 支持 PostgreSQL 作为生产数据库
| 维度 | 评估 |
|------|------|
| 复杂度 | Medium |
| 成本 | Medium |
| 可扩展性 | High |
| 维护性 | Medium |
| 生产适用性 | High |

**优点：**
- 支持多主节点写入
- 企业级高可用性和扩展性
- 丰富的监控和备份工具
- 完整的事务支持

**缺点：**
- 需要额外的基础设施
- 配置和维护复杂度增加
- 开发环境需要额外设置

### 选项 C: 多数据库支持（SQLite + PostgreSQL）
| 维度 | 评估 |
|------|------|
| 复杂度 | High |
| 成本 | Medium |
| 可扩展性 | High |
| 维护性 | Medium |
| 生产适用性 | High |

**优点：**
- 开发环境使用 SQLite，生产环境使用 PostgreSQL
- 最佳开发体验和生产性能
- 渐进式迁移路径

**缺点：**
- 需要维护多数据库兼容性
- 测试复杂度增加
- 可能存在数据库特定语法差异

## 决策

**推荐方案：选项 C - 多数据库支持（SQLite + PostgreSQL）**

### 理由：
1. **开发体验优先**：SQLite 零配置特性保持开发效率
2. **生产就绪**：PostgreSQL 提供生产环境所需的所有特性
3. **渐进式迁移**：允许团队逐步适应生产数据库
4. **测试覆盖**：可以在开发环境测试 SQLite，生产环境测试 PostgreSQL

### 阶段 2: PostgreSQL 支持（2-3周）
1. 添加 PostgreSQL 驱动依赖
2. 实现 PostgreSQL 特定配置
3. 添加连接池参数调优
4. 实现数据库迁移工具（Alembic）

### 阶段 3: 迁移工具（1-2周）
1. 集成 Alembic 迁移工具
2. 创建初始迁移脚本
3. 实现迁移回滚机制
4. 添加迁移验证测试

### 阶段 4: 生产配置（1周）
1. 创建生产环境配置模板
2. 实现环境变量配置
3. 添加数据库备份策略
4. 实现监控和告警

## 影响

### 当前实施状态（2026-07-31 更新）

PostgreSQL 迁移**已完成**，当前数据库策略：

| 环境 | 数据库 | 配置方式 |
|------|--------|----------|
| 开发 (`ENVIRONMENT=development`) | SQLite | `DATABASE_URL=sqlite:///./bilingual_cms.db` (默认) |
| 预发布 (`ENVIRONMENT=staging`) | SQLite | `DATABASE_URL=sqlite:///./data/runtime/bilingual_cms.db` |
| 生产 (`ENVIRONMENT=production`) | PostgreSQL | `DATABASE_URL=postgresql://...` (compose env var) |
| 测试 | SQLite/PostgreSQL | 通过 `DATABASE_URL` 环境变量选择 |

**关键变更：**
- `config.py` 第 46-52 行：生产环境强制要求 PostgreSQL，SQLite 在 `ENVIRONMENT=production` 时抛出 `ValueError`
- `docker-compose.prod.yml`：PostgreSQL 15-alpine + `pg_isready` 健康检查
- `requirements.txt`：包含 `psycopg2-binary>=2.9.9`
- 测试可选 PostgreSQL：通过设置 `DATABASE_URL` 环境变量运行 PostgreSQL 集成测试
- 备份脚本 `scripts/backup.sh` 同时支持 SQLite 和 PostgreSQL

## 风险缓解

1. **兼容性风险**：使用 SQLAlchemy ORM 减少数据库特定语法
2. **迁移风险**：实现完善的迁移测试和回滚机制
3. **性能风险**：添加性能基准测试和监控
4. **运维风险**：提供详细的部署和运维文档

## 监控指标

1. **数据库性能**：查询响应时间、连接池使用率
2. **可用性**：数据库连接成功率、故障转移时间
3. **数据一致性**：事务成功率、数据完整性检查
4. **运维效率**：备份成功率、恢复时间
